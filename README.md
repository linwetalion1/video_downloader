# Image Downloader Explorer

Edge-расширение (Manifest V3) для поиска, предварительного просмотра, фильтрации и массового скачивания изображений с веб-страниц.

Возможности:

- **Поиск на текущей странице** — `<img>`, `srcset`, `<picture>`, `data-src`/`data-lazy`-атрибуты, `background-image`, `meta og:image`/`twitter:image`, прямые ссылки на файлы, динамически подгружаемый контент (MutationObserver).
- **Рекурсивный обход** глубины 0–2 с учётом robots.txt, области обхода (origin/сайт/все домены), лимитов страниц и изображений.
- **Реальные метаданные**: размеры (парсинг заголовков PNG/GIF/JPEG/WebP/BMP/ICO/AVIF/SVG без полной загрузки), вес файла (HEAD + Range), MIME, расширение, fingerprint.
- **Фильтры**: минимальные ширина/высота/вес, соотношение сторон, форматы, исключение иконок/tracking-pixel, логика AND/OR — применяются **локально** мгновенно.
- **Массовый выбор** + виртуализированная сетка, сортировки, экспорт CSV/JSON, копирование URL.
- **Scheduler с очередью** задач (`PAGE_DISCOVERY`, `PAGE_SCAN`, `IMAGE_METADATA`, `IMAGE_DOWNLOAD`), приоритетами, таймаутами, retry для временных ошибок, паузой/продолжением/остановкой.
- **Rate limiting**: случайные задержки, ограниченный параллелизм, авто-backoff при 429/503.
- **Скачивание** через downloads API с автоматически уникальными именами (без перезаписи), структура папок по страницам/доменам/глубине, лимит общего объёма.
- История задач, debug-лог с экспортом, восстановление состояния после закрытия панели.

## 1. Требования

- Node.js ≥ 18.18, npm ≥ 9
- Microsoft Edge (Chromium ≥ 111)

```bash
npm install

npm run build
```

## 5. Загрузка расширения в Edge

### 5a. Готовый файл .crx (рекомендуется, один файл)

Расширение можно упаковать в единый «бинарник» — файл `.crx`, который Edge устанавливает целиком:

```bash
npm run package
```

В папке `release/` появятся:

- `image-downloader-explorer.crx` — установочный файл расширения;
- `image-downloader-explorer.zip` — тот же архив для ручной установки.

Установка `.crx` в Edge (один раз):

1. Откройте `edge://extensions`;
2. Включите «Режим разработчика» (переключатель слева внизу);
3. Перетащите файл `image-downloader-explorer.crx` прямо в окно браузера (на страницу расширений);
4. Подтвердите установку в диалоге — расширение появится и заработает.

Если по какой-то причине Edge не примет `.crx` (например, старая/корпоративная сборка с политиками):

1. Распакуйте `image-downloader-explorer.zip` в любую папку;
2. В `edge://extensions` включите «Режим разработчика»;
3. «Загрузить распакованное» → выберите распакованную папку.

Примечания:

- При первом глубоком поиске Edge запросит доступ к сайту (optional host permissions) — согласитесь; для скачивания с других доменов запрос появится отдельно.
- `npm run package` упаковывает `.crx` **официальным паковщиком Edge** (`msedge.exe --pack-extension=…`) — браузер сам формирует корректный CRX3, который гарантированно принимается при установке. Если `msedge.exe` не найден (или указан `EDGE_PATH`), `.crx` не собирается — используется `.zip` + «Загрузить распакованное». Встроенного «самодельного» CRX больше нет: он может не пройти проверку формата.
- Ключ подписи сохраняется в `keys/edge-key.pem` (в .gitignore): при повторной упаковке ID расширения остаётся стабильным. Не публикуйте этот ключ.
- Edge установит `.crx` с предупреждением вроде «расширение не из магазина» — это нормально для локальной установки.

### Если Edge пишет «This extension is not from any known source…» (не даёт включить)

Это защита от «подсунутых» расширений. Порядок действий:

1. На `edge://extensions` найдите карточку расширения и нажмите **«Удалить»** — старую версию без ключа Edge не «узнаёт»;
2. Включите **«Режим разработчика»** (переключатель в левом нижнем углу страницы расширений) — без него sideload-расширения блокируются;
3. Перетащите **новый** `image-downloader-explorer.crx` (из `release/`, собранный после `npm run package`, с ключом в manifest) в окно браузера и подтвердите установку — теперь тумблер включения активен;
4. Если предупреждение всё равно остаётся — используйте обходной путь, который не затрагивается этой защитой вообще: распакуйте `.zip` и выберите папку через **«Загрузить распакованное»** (режим разработчика включён);
5. Если на странице написано «Управляется вашей организацией» — блокировку ставит корпоративная политика (`ExtensionInstallBlocklist`/`ExtensionSettings`), и разрешить sideloading может только администратор.

Манифест теперь содержит поле `"key"` (стабильный ключ разработчика), поэтому Edge воспринимает расширение как «известный источник», а ID не меняется между пересборками.

### 5b. Из исходников (unpacked)

1. Откройте `edge://extensions`.
2. Включите «Режим разработчика» (Developer mode).
3. «Загрузить распакованное» → выберите папку `dist/` (после `npm run build`).
4. Закрепите расширение и откройте side panel (клик по иконке расширения открывает панель автоматически).

## 7. Архитектура

```

├── manifest.json            # MV3: permissions, optional_host_permissions, side_panel
├── sidepanel.html           # входной HTML React-панели
├── scripts/
│   ├── build.mjs            # 3 сборки: background.js (ESM), content.js (IIFE), sidepanel (React)
│   └── make-icons.mjs       # генерация PNG-иконок без внешних зависимостей
├── src/
│   ├── background/service-worker.ts   # роутер сообщений, владелец Crawler, permissions, история
│   ├── content/                       # контент-скрипт (инжектится по требованию через activeTab)
│   │   ├── content.ts                 # точка входа, обработчик IDE_SCAN_PAGE
│   │   ├── scanner.ts                 # сканирование + lazy-scroll + MutationObserver-окно
│   │   ├── dom-image-detector.ts      # детектор всех типов изображений (работает и в SW)
│   │   ├── link-detector.ts           # извлечение ссылок для обхода
│   │   └── mutation-monitor.ts        # ограниченный по времени MutationObserver
│   ├── crawler/
│   │   ├── crawler.ts                 # оркестратор discovery→scan→metadata→download
│   │   ├── scheduler.ts               # центральный планировщик (concurrency/timeout/retry)
│   │   ├── queue.ts                   # приоритетная очередь задач
│   │   ├── deduplicator.ts            # canonical URL страниц, группы вариантов, fingerprint
│   │   ├── rate-limiter.ts            # случайные задержки + backoff
│   │   ├── robots.ts                  # парсер robots.txt (best-effort)
│   │   └── http.ts                    # fetch с таймаутом/классификацией ошибок
│   ├── images/
│   │   ├── metadata.ts                # HEAD + Range-sniff, парсеры заголовков форматов
│   │   ├── filters.ts                 # фильтр-движок, сортировки, выбор
│   │   ├── fingerprint.ts             # sha1-хеш начала файла
│   │   └── downloader.ts              # downloads API + blob-фолбек, имена файлов
│   ├── storage/settings.ts            # chrome.storage: настройки, снимок задачи, история
│   ├── shared/                        # types, constants, utils (без зависимостей от UI)
│   └── ui/sidepanel/                  # React (Tabs: Найти / Результаты / Загрузка / Настройки)
└── tests/                             # vitest + jsdom (51 тест)
```

Ключевой принцип: **UI не знает о сети**, crawler не знает о React, downloader не зависит от React. Общение — через порт и типизированные сообщения (`types.ts`).

## 8. Permissions

`manifest.json`:

- `activeTab` — сканирование текущей вкладки без `<all_urls>`;
- `storage` — настройки, снимок задачи, история;
- `downloads` — скачивание файлов;
- `scripting` — инжекция `content.js`;
- `sidePanel` — side panel UI;
- `optional_host_permissions: ["http://*/*", "https://*/*"]` — запрашиваются точечно (`chrome.permissions.request`) только для origins, с которыми работает пользователь.

`<all_urls>` не запрашивается.

## 9. Ограничения browser security

- Расширение **не** отключает CSP, не выполняет код страниц, не использует `eval`, не подменяет cookies/заголовки и не обходит CAPTCHA/авторизацию/WAF.
- Если ресурс недоступен из-за CORS/отсутствия host-разрешения — показывается ошибка и кнопка «Открыть оригинал».
- Случайные задержки предназначены только для снижения нагрузки на сайты. При 429/503/Retry-After включается backoff (×2 до `maxBackoffMs`), при нормализации ответов интервал постепенно возвращается. Это **не** механизм обхода антибот-защиты.

## 10. Crawler

Жизненный цикл одного обхода (ТЗ §66):

```
DOM Scanner → Discovery → Normalizer → Deduplication → Metadata Resolver
→ Filter Engine → Preview/Selection UI → Crawler → Rate Limiter
→ Download Scheduler → Download Queue → Progress/Error Handling
```

- **Приоритеты (§21)**: текущая страница и её изображения раньше, затем уровень 1, затем уровень 2; скачивания — по команде пользователя с наивысшим приоритетом.
- **Дедупликация (§9)**: canonical URL страниц (без hash и `utm_*`), группы вариантов изображений (`a.jpg`, `a.jpg?w=800`, `a.jpg?q=…` — одно изображение; `a.jpg?id=1` и `?id=2` — разные), fingerprint контента как вторичный уровень.
- **Ограничения**: глубина ≤ 2, максимум страниц (по умолчанию 100), максимум изображений (1000), общий объём скачивания (2 ГБ), visited/queued Set'ы — циклы невозможны.
- **robots.txt**: кэш по origin, «*\»-группа, Allow/Disallow, wildcard `*` и `$`, Crawl-delay учитывается как минимальная задержка. Отказ не блокирует обход — страница просто пропускается. Это best-effort соблюдение правил сайта.
- Область обхода: «Только origin» (по умолчанию), «текущий сайт» (eTLD+1 — приближение без PSL-базы, см. §13), «все домены». Не посещаются `mailto:`, `tel:`, `javascript:`, `data:`, `blob:`, не-HTML файлы, очевидные logout/delete/login URL.
- Таймауты: страница 15 с, изображение 10 с, скачивание 60 с (настраиваются). Retry только для временных ошибок (timeout, сеть, 5xx, 429), max 2 попытки; 401/403/404 не повторяются.

## 11. Rate limiting

- Задержки задаются диапазонами (мин–макс), реальная задержка — `min + Math.random() * (max - min)`.
- Отдельные диапазоны для страниц, проверки изображений и скачиваний.
- Параллелизм scheduler'а 1–8 (по умолчанию 2); `Promise.all` на сотни запросов не используется — только центральная очередь.
- Авто-backoff на 429/503 и при сетевых ошибках, плавное возвращение к норме.

## 12. Сборка и детали реализации

- **Service worker** владеет наследственным состоянием: снимок задачи (`JobView`) сохраняется в `chrome.storage.local` и восстанавливается при повторном открытии панели после рестарта SW.
- **Метаданные без полной загрузки**: PNG/GIF/BMP/JPEG/WebP/ICO/AVIF размеры читаются из заголовков первых байт (HEAD + Range до 64 КБ); SVG определяется отдельно и помечается «размер неизвестен», если нет атрибутов `width/height`.
- **Имена файлов (§28)**: Content-Disposition → имя из URL → `alt` → `title` → сгенерированное; конфликты решаются автоматически (`image.jpg`, `image (1).jpg`) через `conflictAction: "uniquify"`.
- **Виртуализация**: сетка рендерит только видимые карточки (overscan), thumbnails с `loading="lazy"`.
- **Доступность (§58)**: навигация с клавиатуры, `Ctrl+A`/`Ctrl+D`/`Esc`/`Space`, aria-атрибуты, достаточный контраст.

## 13. Известные ограничения

- Определение «текущего сайта» использует приближение eTLD+1 без публичного списка суффиксов (для `co.uk`, `com.br` и т. п. работает корректно; экзотические многоуровневые TLD могут считаться неточно).
- CSS-фоны из внешних таблиц стилей не анализируются (только inline-стили и computed-стиль `body`); `<style>`-блоки не парсятся.
- `data:`/`blob:` URL игнорируются как кандидаты на скачивание.
- При закрытии панели задача продолжает выполняться в service worker; после рестарта SW снимок восстанавливается, но очереди заданий восстанавливаются как «ожидающие» (возможен повторный запуск с кнопки).

## 14. Отладка (когда «картинок не находит»)

Встроенный отладочный слой:

- **Вкладка «Найти» → блок «Отладка»**: сводка последнего скана (кандидаты, `<img>`, ссылки, shadow roots, canvas, автоскролл, мутации, разбивка по типам источников) и живой лог событий с кнопками «Копировать лог» / «Скачать лог файл».
- **Логи в service worker**: инжекция контент-скрипта, ошибки доступа, повторные попытки, итог каждого скана — всё видно в панели и в экспортируемом логе (вкладка «Загрузка» → «Экспорт debug log»).
- **Консоль самой страницы**: контент-скрипт пишет `[IDE] scan OK: hits=…, imgElements=…, shadowRoots=…` — открывается в DevTools вкладки.
- **Глубокий обход**: сканер проникает в открытые shadow roots (Web Components/SPA, например Google Labs); закрытые shadow roots и canvas-контент не читаются — в сводке видно, если причина в них.
- Если скан упал — в «Найти» появляется красный баннер с текстом ошибки (например «Нет доступа к вкладке», «Эту страницу нельзя сканировать»).
